# コードレビュー: iOS App Recorder (第4回)

レビュー日: 2026-02-23
レビュアー: iOS 音声/動画エンジニア視点

## 全体評価

3回のレビューを経てコードの品質は高い。ゼロコピー IOSurface キャプチャ、ロックフリー SPSC リングバッファ、プライミング補償付き AAC エンコード、drawable ライフサイクル管理など、リアルタイム A/V パイプラインの主要課題を的確に解決している。以下は第3回で見落とされた、あるいは新たに浮上した指摘事項。

---

## High

### 1. ~~AudioEncoder: CMTimeMakeWithSeconds の浮動小数点丸めで PTS が累積ドリフトする~~ ✅ 修正済み

- **ファイル:** `AudioEncoder.m:383-384`
- **問題:** `CMTimeMakeWithSeconds((double)sampleOffset / self.sampleRate, ...)` は double → int64_t 変換で浮動小数点の丸めが入る。48000Hz で1時間録画すると sampleOffset は ~1.7億サンプルに達し、double の53ビット仮数部では精度が劣化する。長時間録画で PTS が壁時計からドリフトし、A/V sync ずれとして顕在化し得る。
- **修正内容:** 整数演算のみの `CMTimeMake(sampleOffset, (int32_t)self.sampleRate)` に変更。

### 2. ~~VideoEncoder: drawable 保持数が Metal drawable プールサイズに達し nextDrawable がストールする可能性~~ ✅ 修正済み

- **ファイル:** `VideoEncoder.m:10, 174-204`
- **問題:** `ENCODER_QUEUE_DEPTH = 2` は dispatch ブロック数を制限するが、drawable が解放されるのは VT 出力コールバック。dispatch キューに2ブロック + VT 内部で1エンコード中 = 3 drawable 同時保持。Metal の drawable プールはデフォルト3。全保持で nextDrawable がブロックしゲームがストールする。
- **修正内容:** セマフォの signal を VT 出力コールバック内（drawable 解放と同タイミング）に移動。エンコード失敗・セッション破棄済みパスでは dispatch ブロック内で signal。

### 3. ~~startRecording / stopRecordingWithCompletion の同時呼び出しに対する排他がない~~ ✅ 修正済み

- **ファイル:** `RecorderCore.m:54-166, 168-204`
- **問題:** isRecording は atomic だがチェックと状態変更の間に排他がない。STOP 完了チェーン実行中に START が呼ばれると FrameCapture.delegate / AudioCapture.delegate が新旧 RecorderCore から交互に設定され状態が不整合になる。
- **修正内容:** `recordingQueue` (シリアルキュー) を導入。`startRecording` は dispatch_sync、`stopRecordingWithCompletion:` は dispatch_async でシリアライズ。`forceResetRecordingState` は緊急用のため recordingQueue を経由しない。

## Medium

### 4. ~~AudioCapture: HookedUnitInfo の origCallback/origRefCon 書き込みと RT スレッドの読み取りに happens-before がない~~ ✅ 修正済み

- **ファイル:** `AudioCapture.m:60-71, 170-173`
- **問題:** `hooked_AudioUnitSetProperty` で info->origCallback を書き込み後 sCapturedUnit に release store するが、renderCallbackWrapper は origCallback を**先に**読み、sCapturedUnit の acquire load は**その後**。release/acquire ペアが正しく対応せず、RT スレッドが stale な origCallback を読む可能性がある（形式的データレース）。
- **修正内容:** `origCallback` を `_Atomic(AURenderCallback)`、`origRefCon` を `_Atomic(void *)` に変更。書き込み側は `origRefCon` を relaxed store → `origCallback` を release store。読み取り側は `origCallback` を acquire load → `origRefCon` を relaxed load。

### 5. ~~RecorderCore: startRecording の部分失敗クリーンアップが非同期 stop の完了を待たない~~ ✅ 修正済み

- **ファイル:** `RecorderCore.m:119-147`
- **問題:** `[self.videoEncoder stopWithCompletion:nil]` は async 実行だが直後に `self.videoEncoder = nil` で ARC release。VTCompressionSession の破棄タイミングが不確定。
- **修正内容:** 部分失敗時はセマフォ付きの completion でエンコーダの stop 完了を同期的に待ってから nil 化 (5秒タイムアウト)。

### 6. ~~FrameCapture: @try/@catch が ARC で安全でない~~ ✅ 修正済み

- **ファイル:** `FrameCapture.m:81-145`
- **問題:** ARC 環境で `-fobjc-arc-exceptions` なしの @try/@catch は、例外発生時にスコープ内のローカル変数 (pixelBuffer 等) がリークする。
- **修正内容:** @try/@catch を除去。各 API 呼び出しの戻り値チェック (respondsToSelector、CVReturn、NULL チェック) で十分。

### 7. ~~映像サイズの偶数化が maxCaptureSize 超過時のスケーリングパス内にしかない~~ ✅ 修正済み

- **ファイル:** `RecorderCore.m:77-88`
- **問題:** キャプチャサイズがそのまま使われるパスでは偶数化されない。奇数ピクセル幅/高さの場合 VTCompressionSession の出力が壊れるか AVAssetWriter が拒否する。
- **修正内容:** maxCaptureSize 比較の外側で常に `width & ~1`, `height & ~1` を適用。

### 8. ~~AudioEncoder: reconfigureWithSampleRate が dispatch_sync チェーンで drain スレッドを長時間ブロックする~~ ✅ 修正済み (コメント追記)

- **ファイル:** `AudioEncoder.m:236`
- **問題:** drain タイマーハンドラ → delegate → reconfigure → dispatch_sync(encoderQueue) のチェーン。reconfigure 中のバッファ再割り当て + 旧データエンコードの間 drain スレッドがブロックされ、リングバッファが溢れて RT スレッドの音声がドロップする可能性。
- **修正内容:** フォーマット変更は稀 (FMOD エンジン再構成時のみ) であり、drainQueue → encoderQueue は一方向でデッドロックしないため、制約と許容理由をコメントとして明記。

## Low

### 9. ~~ControlServer: LIST コマンドがファイル名のみ返し PULL に必要なフルパスがない~~ ✅ 修正済み

- **ファイル:** `ControlServer.m:355-374`
- **問題:** LIST はファイル名のみ返すが PULL はフルパスを要求。クライアントが NSTemporaryDirectory() のパスを知っている前提。
- **修正内容:** LIST でフルパスを返すよう変更。

### 10. ~~RecorderLog.h: 複数スレッドからの fprintf が行単位でインターリーブする~~ ✅ 修正済み

- **ファイル:** `RecorderLog.h:28-35`
- **問題:** タイムスタンプの fprintf と本文の vfprintf が別システムコール。間に別スレッドの fprintf が割り込む可能性。
- **修正内容:** `flockfile/funlockfile` で一連の fprintf/vfprintf をアトミックに保護。

### 11. FrameCapture: captureSize の atomic 更新が非録画時も毎フレーム実行される

- **ファイル:** `FrameCapture.m:64-79`
- **問題:** 非録画時も全 nextDrawable で atomic CGSize 比較・更新が走る。CGSizeEqualToSize ガードがあるため実質ノーオペだが、不要な計算。
- **実際のリスク:** 微小。ARM64 atomic は数ナノ秒。captureSize は startRecording で参照されるため、非録画時にも更新する設計は意図的。修正不要。

### 12. ~~cleanupTempFiles: NSIRD_ ディレクトリのサイズが不正確~~ ✅ 修正済み

- **ファイル:** `RecorderCore.m:243-244`
- **問題:** attributesOfItemAtPath はディレクトリ自体のメタデータサイズ（64-96 bytes）を返し、内容物の合計ではない。freedBytes が実際より少なく報告される。
- **修正内容:** `enumeratorAtPath:` で再帰的にファイルサイズを合算。
