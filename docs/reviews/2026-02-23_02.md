# コードレビュー: iOS App Recorder (第2回)

レビュー日: 2026-02-23
レビュアー: iOS 音声/動画エンジニア視点

## 全体評価

前回のレビュー指摘事項はすべて適切に修正されている。アーキテクチャは堅実で、RT セーフなオーディオパス、ゼロコピー IOSurface キャプチャ、drawable 保持によるエンコード安全性など、専門的な設計が光る。以下は現状のコードに残る新たな指摘事項。

---

## Critical

### 1. ~~stopRecording → startRecording の非同期チェーン競合~~ ✅ 修正済み

- **ファイル:** `RecorderCore.m`
- **問題:** `stopRecordingWithCompletion:` の非同期完了チェーンが `weakSelf` 経由でエンコーダ/muxer にアクセスしている。`isRecording = NO` が同期的にセットされた後、完了チェーンが実行される前に `startRecording` が呼ばれると、`weakSelf.audioEncoder` と `weakSelf.muxer` が**新しいインスタンス**を指すようになる。
- **結果:**
  - 旧 AudioEncoder: `stopWithCompletion:` が呼ばれず、AudioConverter がリークする
  - 旧 MP4Muxer: `finishWritingWithCompletionHandler:` が呼ばれず、不完全な MP4 が残る
  - 新 AudioEncoder/MP4Muxer: 開始直後に stop/finish され、新しい録画が即座に壊れる
- **修正内容:** チェーン開始前にローカル変数 (`ve`, `ae`, `mux`) でインスタンスをキャプチャし、`weakSelf` 経由のアクセスを排除。

---

## High

### 2. ~~maxCaptureSize のタイプミス — 2060 vs 2560~~ ✅ 修正済み

- **ファイル:** `RecorderCore.m`
- **問題:** `_maxCaptureSize = CGSizeMake(2060, 1440)` — おそらく 2560 x 1440 の意図。
- **修正内容:** `CGSizeMake(2560, 1440)` に修正。

### 3. ~~VTSessionSetProperty の戻り値が未チェック~~ ✅ 修正済み

- **ファイル:** `VideoEncoder.m`
- **問題:** 全 `VTSessionSetProperty` 呼び出しの `OSStatus` が無視されている。特に `kVTCompressionPropertyKey_RealTime` が失敗すると、VT がオフラインモードで動作しエンコード遅延が増大する。
- **修正内容:** `RealTime` と `ProfileLevel` の戻り値をチェックし、失敗時に WARNING ログを出力。

### 4. ~~encodeCount の非アトミックインクリメント~~ ✅ 修正済み

- **ファイル:** `VideoEncoder.m`
- **問題:** `++self.encodeCount` がレンダースレッドで実行されるが、`encodeCount` は `encoderQueue` 上の `stopWithCompletion:` からも読まれる。nonatomic プロパティへの異スレッドアクセスは data race。
- **修正内容:** `static _Atomic int64_t sEncodeCount` に変更し、`atomic_fetch_add_explicit` / `atomic_load_explicit` で操作。

---

## Medium

### 5. ~~非インターリーブ音声パスで毎回 malloc/free~~ ✅ 修正済み

- **ファイル:** `AudioEncoder.m`
- **問題:** `_enqueuePCM:` の非インターリーブパスが呼び出しごとに `malloc` + `free` を実行。FMOD は非インターリーブ出力を使うため、全音声コールバックでヒープアロケーションが発生する。
- **修正内容:** `interleavedTempBuffer` / `interleavedTempBufferSize` プロパティを追加し、サイズ不足時のみ再割り当て。

### 6. ~~atomic captureSize が毎フレーム書き込まれる~~ ✅ 修正済み

- **ファイル:** `FrameCapture.m`
- **問題:** 全フレームで `self.captureSize = ...` を実行。atomic プロパティのスピンロックが毎フレーム発生。
- **修正内容:** `CGSizeEqualToSize` で比較し、変更時のみ atomic setter を呼ぶように変更。

### 7. ~~STOP タイムアウト時に録画が放置される~~ ✅ 修正済み

- **ファイル:** `ControlServer.m`, `RecorderCore.m`, `RecorderCore.h`
- **問題:** 30 秒タイムアウト後、クライアントに ERR Timeout を返すが録画は進行し続ける。
- **修正内容:** `RecorderCore` に `forceResetRecordingState` メソッドを追加。タイムアウト時にキャプチャ停止・デリゲート解除・全プロパティ nil クリーンアップを実行。

### 8. ~~RecorderLog のファイルポインタ初期化がスレッドセーフでない~~ ✅ 修正済み

- **ファイル:** `RecorderLog.h`
- **問題:** `s_logfile == NULL` チェック → `fopen` に排他制御がなく、複数スレッドからの初回呼び出しで FILE* がリークする。
- **修正内容:** `dispatch_once` で `fopen` + `setlinebuf` をガード。

## レビュー外で発見・修正した追加バグ

### 12. ~~captureSize が録画開始前に更新されず映像が横に引き伸ばされる~~ ✅ 修正済み

- **ファイル:** `FrameCapture.m`
- **問題:** `captureSize` の更新が `if (!self.capturing)` ガードの内側にあり、録画開始前は常に `(0, 0)`。`startRecording` がフォールバックの `maxCaptureSize` (2560x1440 = 16:9) を使い、iPad の 4:3 フレームが VT エンコーダで 16:9 に引き伸ばされていた。
- **修正内容:** `captureSize` 更新を早期リターンの前に移動し、`capturing=NO` でも `nextDrawable` のたびにテクスチャサイズが反映されるようにした。
